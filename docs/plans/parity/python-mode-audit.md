# Python-mode non-regression audit

Compared the Copilot module's source changes against `origin/develop` (`git diff origin/develop -- src src-util`). The new Java engine, selector, server-tool, HTTP, and OCR classes have no pre-existing Python behavior to preserve. Existing-file changes are audited below.

| File | Change from `origin/develop` | Python-mode impact | Decision |
|---|---|---|---|
| `src/com/etendoerp/copilot/process/GetMCPConfiguration.java` | MCP configuration generation moved from the Python MCP listener (`context.url.copilot.mcp` or `localhost:<copilot.port.mcp>`, then `/<agentId>/[direct/]mcp`) to the Java servlet (`/sws/copilot/mcp/<agentId>/[direct/]mcp`). | A global switch to the Java URL would break Python MCP clients while `copilot.engine=python` remains the default. | Keep the legacy Python base URL and route when engine is Python; use the Java servlet URL only for `java` and `java-strict`. Python's existing `/<identifier>/mcp` and `/<identifier>/direct/mcp` routes confirm the legacy URL flow. |
| `src/com/etendoerp/copilot/rest/RestServiceUtil.java` | Request dispatch moved to `CopilotEngineSelector`; client-tool fields and tool-call short-circuiting were added; the structured-output payload key is now `output_schema` (the key Python reads, as on the epic branch); `setEventStreamMode` became public. | Python remains dispatched through `PythonCopilotEngine`, which forwards the same JSON to its historical HTTP routes. Client tool exchange is Java-only; the visibility change has no runtime behavior impact. Python only reads `output_schema` (schemas.py:55, agent.py:292-296), so the old key was never consumed: this deliberately fixes structured output in Python mode. | Keep the selector dispatch; leave Python client-tool fields unused, as the previous runtime had no such protocol; keep `output_schema` for both engines (intentional behaviour fix). |
| `src/com/etendoerp/copilot/util/CopilotUtils.java` | Vector DB operations were moved from Python HTTP endpoints to the in-process Java pgvector store; file-source identity was added; SWS identity resolution was extracted for the Java tool context. | Unconditional Java KB calls break default Python sync and make all agents fail without pgvector. Refreshed SWS entities preserve the existing user/role/organization/warehouse identity used for Python token generation. | Restore Python calls to `/addToVectorDB`, `/ResetVectorDB`, and `/purgeVectorDB` whenever `copilot.engine=python`; use Java store only in Java modes. Keep identity refresh because it preserves the same SWS identity and avoids detached entities. |
| `src/com/etendoerp/copilot/util/FileUtils.java` | Knowledge-source indexing now passes `CopilotAppSource` identity to the Java indexer. | Python multipart uploads do not need the source ID and retain the prior request fields. | Keep source ID for Java indexing; the Python path ignores it and emits the original multipart payload. |
| `src/com/etendoerp/copilot/process/SyncAssistant.java` | Knowledge sync now records per-agent Java KB failures and skips empty Java KB resets. | Empty Python KB sync retains its old reset/upload/purge sequence; Python errors still use the original process-level error path. | Branch on engine mode. Java agents without KB sources can synchronize without pgvector; a Java agent with KB sources receives its own clear KB error. |
| `src/com/etendoerp/copilot/startup/CopilotSyncStartup.java` | Startup completion now honors per-agent KB errors returned by `SyncAssistant`. | Python returns its legacy result shape, so there are no `syncErrors` to change prior completion behavior. | Treat absent `syncErrors` as the legacy success case; do not mark a Java agent with a failed KB sync as synchronized, while marking unaffected agents. |
| `src/com/etendoerp/copilot/engine/PythonCopilotEngine.java`, `ChatModelFactory.java`, and `CopilotEngineSelector.java` | Added the legacy Python transport as an engine, Java chat-model creation, and engine selection/fallback. | Python is the default and must retain prior HTTP behavior. | Keep the historical endpoint, POST, JSON, response parsing, streaming, and connection-error behavior unchanged; Python selection explicitly chooses this engine. Java model and selector code is intentional and doesn't change the Python path. |
| `src/com/etendoerp/copilot/engine/CopilotEngine.java`, `LangChain4jEngine.java`, `ClientToolSupport.java`, `src/com/etendoerp/copilot/engine/mcp/**`, `src/com/etendoerp/copilot/engine/tool/**` (including OpenAPI FLOW supplementary tools and `ToolExecutionContext`), `src/com/etendoerp/copilot/engine/tool/http/**`, `src/com/etendoerp/copilot/rest/CopilotMcpServlet.java`, `src/com/etendoerp/copilot/tool/SimpleOcrTool.java`, `src/com/etendoerp/copilot/util/OcrSchemaBuilder.java`, and `PdfRenderer.java` | Added Java engine/tool execution and Java-only client tool, MCP, HTTP, OCR, active-workspace tracking, and per-question OpenAPI FLOW tools. | These paths execute only when Java is selected; Python mode does not enter them. | Intentional Java-only additions; no Python caller migration. |

| `src/com/etendoerp/copilot/config/ProviderCredentials.java`, `RestServiceUtil.java`, `PythonCopilotEngine.java`, `copilot/core/utils/models.py`, `copilot/core/utils/agent.py`, and `copilot/core/routes.py` | The Java request builder resolves credentials and sends them in request-scoped `extra_info.llm`; Python prefers this configuration and retains environment fallback. Request logging redacts the key, and the Python context log records only extra-info field names. | Python mode remains supported; the additional credential is internal request data and is not emitted in request logs. Legacy properties and environment variables remain fallbacks. | Keep the credential handoff until Python is removed; never log or persist the key. |
| `docs/java-engine.md` | Documents DB-backed keys, legacy fallback and deprecation schedule. | No runtime impact. | Keep documentation aligned with the transition. |
No pre-existing hook or event-handler implementation was modified in this diff. `src-util` contains no separate Python-mode source change.
